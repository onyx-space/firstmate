## docs/watcher-continuity.md: the lookup description (lines 106-109)

Which lane serves a repository is asked of `olink route`, whose answer reads the fleet's joined map, `<origmd clone>/ref/lanes.json` - which `scripts/owners.mjs` writes from the machine file's lane list and each lane's own checkout - together with this endpoint's own registration; only a lane registered on this endpoint counts, because a repository another machine maintains is that machine's own dispatch.
When that map is absent or silent about the repository, the same question is answered from the endpoint's machine file, whose `Long-lived maintenance lanes` line carries each lane's name and directory, plus the repository each lane's own checkout points at - so a lane checking out a different repository takes the archive path either way.
The dispatch addresses the lane by the registered name olink resolves, and the endpoint key it needs comes from olink's own answer (or, on the fallback, from olink's own config) rather than a second copy of the machine-key pairing.
A dispatch that cannot be made - no registered name, no wire on the machine, or a send whose own report does not put the payload in the mailbox, which wire can report as `unreadable` while still exiting 0 - leaves the note and its row exactly as a failed archival does: retryable and named on the acknowledgement's own output, never reported as delivered.
