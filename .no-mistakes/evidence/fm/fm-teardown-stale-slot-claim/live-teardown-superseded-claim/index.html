Live evidence - fm-teardown stale slot claim on a reused Treehouse slot

40/40 machine assertions passed. Every case drove the real bin/fm-teardown.sh executable against a real git project, a real treehouse get pool owner stamp, real tmux panes whose endpoints the product's own classifier reads, a real firstmate home, and the real treehouse return.

How each case was stood up
  1. treehouse.toml pins the pool root to an isolated temp root; a real treehouse get stamps owner_started_at in the pool's own treehouse-state.json.
  2. Two real firstmate task records name that slot; the occupant's spawn_gen is after the owner stamp, the stale record's is ~13h before it.
  3. A real tmux server (isolated with TMUX_TMPDIR) holds both records' endpoints: both read alive through fm_backend_agent_state, so endpoint liveness alone resolves nothing.
  4. FM_HOME=<case>/home FM_ROOT_OVERRIDE=<repo> bin/fm-teardown.sh <task> --force is run as the end user runs it.
