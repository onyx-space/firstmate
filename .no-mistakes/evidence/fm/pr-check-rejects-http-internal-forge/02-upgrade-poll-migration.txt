Scenario: upgrading firstmate must not make an already-armed merge watch go
stale. The watcher byte-compares each state/<id>.check.sh against the tracked
bin/fm-pr-poll.sh, so an upgrade that changes those bytes would otherwise leave
every live watch rejected ("check: rejected unauthenticated state checks") and
its merge unobserved. The migration must re-anchor the watch onto the new bytes
without touching task metadata, be idempotent, and never fail silently.

The "pre-change bytes" used below are the real bin/fm-pr-poll.sh from the base
commit of this change:
$ git show 3e447e7fbd668e3d9424e211102e9315f4fd5fa1:bin/fm-pr-poll.sh
base sha256   = e87aae384ec62ae28f78a0779020f52f7b891ba0cafea2551b5a2c4e967870cf
current sha256= f1cdadd397e405cf8fc4b565d42e5addafdc1ac026d96f9e6125eadcff214a65

--- RED, BEFORE THE MIGRATION: the reported failure mode ------------------------
A watch armed with the pre-change bytes, while its pull request is already
merged in the forge:

$ . bin/fm-pr-lib.sh; fm_pr_poll_artifacts_valid <state> task-r <current template>
REJECTED

$ bin/fm-watch.sh     # the real watcher, forge reports merged:true
check: rejected unauthenticated state checks: /tmp/fm-live/home-red/state/task-r.check.sh
poll hits against the live forge while rejected: 0
poll artifacts after the rejection:
task-r.check.sh
task-r.meta
task-r.pr-poll
task-r.pr-poll-registration
=> the merge was silently missed and MAIN was woken about a rejected check.

$ bin/fm-update.sh
